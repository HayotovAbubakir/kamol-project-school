# Cloudflare fresh start

## Database decision

This deployment starts with a new, empty Cloudflare D1 database. The old Supabase contents were test data and are **not being migrated**. The project does not connect to, modify, or delete the Supabase project. Its owner may delete that old project at any time.

Production resources:

- D1: `kamol-school-db`
- R2: `kamol-files`
- Worker: `kamol-project-school`

Apply the SQL migrations to the remote D1 before deployment:

```powershell
npx wrangler d1 migrations apply kamol-school-db --remote
npm.cmd run build
npx wrangler deploy
```

## Required credentials

| Name | Use | Handling |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | GitHub Actions deploy only; local deploy uses `wrangler login` | Owner creates in Cloudflare **My Profile → API Tokens**, with Workers Scripts Edit, D1 Edit, Workers R2 Storage Edit. Add with `gh secret set CLOUDFLARE_API_TOKEN`. |
| `CLOUDFLARE_ACCOUNT_ID` | GitHub Actions | Read from `npx wrangler whoami`; saved as a GitHub secret. |
| `CLOUDFLARE_API_URL` | Owner seed, webhook, and health check | Set to the deployed HTTPS Worker URL; save as GitHub secret after first deploy. |
| `AUTH_SECRET` | Worker session/JWT signing | Generated securely and installed as a Worker secret. |
| `BOT_API_SECRET` | Internal bot-to-Worker authorization | Generated securely and installed as a Worker secret. |
| `TELEGRAM_BOT_TOKEN` | Telegram bot API and Mini App authentication | Only the owner can obtain this from BotFather. Add as a Worker secret and GitHub secret. |
| `TELEGRAM_WEBHOOK_SECRET` | Telegram webhook request verification | Generated securely and installed as a Worker secret. |

`OWNER_SEED_SECRET` is a separate, generated one-time bootstrap credential, installed as a Worker secret. The owner password is never generated by the project or stored in a file: enter it privately into the `OWNER_SEED_PASSWORD` environment variable only while running the seed script.

## Owner seed

After deploy, set `CLOUDFLARE_API_URL` and `OWNER_SEED_SECRET` in the local PowerShell session. To enter the owner password without echoing it, use:

```powershell
$secure = Read-Host "Owner paroli" -AsSecureString
$env:OWNER_SEED_PASSWORD = [System.Net.NetworkCredential]::new('', $secure).Password
npm.cmd run owner:seed
Remove-Item Env:OWNER_SEED_PASSWORD
Remove-Variable secure
```

The password must contain at least 12 characters. The seed endpoint will not overwrite an existing owner.

## Telegram setup

Only after the owner has supplied the bot token, install it with `npx wrangler secret put TELEGRAM_BOT_TOKEN` and save it for GitHub Actions with `gh secret set TELEGRAM_BOT_TOKEN`. Set up the webhook after the live URL is known:

```powershell
$env:CLOUDFLARE_API_URL = "https://<deployed-worker-url>"
npm.cmd run bot:webhook:set
Remove-Item Env:CLOUDFLARE_API_URL
```

The webhook setup script also configures the bot commands and Mini App menu. Confirm with Telegram `getWebhookInfo` that `last_error_message` is absent before considering the bot verified.

## GitHub Actions

Pushes and pull requests always run lint, tests, and build. The deploy job skips successfully with a clear message when `CLOUDFLARE_API_TOKEN` is not present. To enable automatic deploys, create a Cloudflare API token with the three permissions above and run:

```powershell
gh secret set CLOUDFLARE_API_TOKEN
```

GitHub prompts for the value; do not put it in a command argument or chat. Also set `CLOUDFLARE_API_URL`, `TELEGRAM_BOT_TOKEN`, `AUTH_SECRET`, `BOT_API_SECRET`, and `TELEGRAM_WEBHOOK_SECRET` as GitHub secrets before expecting automatic deployment and webhook configuration. Local Worker secrets are installed separately using Wrangler.
